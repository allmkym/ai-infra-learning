## 用户回答的直接证据

当调用方有一个 string str 和 vector<int> numbers，并调用参数为 string_view sv、vector<int>& input_num 的函数时，用户回答：

> 1.不是，原字符由str持有
> 2.是访问名称，因为参数传入的是引用
> 3.会保持原样不变，无法获得输入的整数

对应问题依次是：string_view 按值传递是否复制字符；vector 引用参数是否创建容器副本；改成 vector 按值参数后函数内追加是否影响调用方。三项回答均正确。

对于返回局部 string s 的 string 函数，以及返回局部 string s 的 string_view 函数，用户解释：

> 第一个是按值返回string，调用方读取安全。如果调用方直接用返回值构造一个string，编译器还可能会触发NRVO，这样的话，实际上函数内的string s其实就在调用方构造的string的内存上，非常安全。
> 第二个是按值返回一个string_view,它不拥有字符串,真正拥有字符串的是局部对象s,调用方接收了返回的string_view时,局部对象s已经析构,string_view指向的内存已不可用,造成了悬空引用,是不安全的.

判断正确。教学补充是区分可选 NRVO 与保证的消除，并说明返回 owning string 的安全性不依赖 NRVO。原回答已经使用“可能”，不能夸大为用户误以为 NRVO 总是发生。
